# Tauri 外壳：Windows 桌面 + Android

一套 Tauri 工程同时承载桌面与安卓，前端产物是 `dist/`，由 `pnpm build:tauri` 生成。

## 目录

```
dist/                  前端产物（pnpm build:tauri）
rust-toolchain.toml    锁定 Rust 工具链（与 Cargo.lock 一起保证可复现）
src-tauri/
  Cargo.toml           模块 feature 开关、依赖版本锁
  tauri.conf.json      窗口、CSP、打包目标、安卓 minSdk
  capabilities/        IPC 权限（只开 core:default）
  icons/               由 app-icon.png 生成，勿手改
  vendor/              内置的 tauri-plugin-opener（见下）
  src/
    main.rs            桌面入口
    lib.rs             run()，桌面与安卓共用；单实例、启动失败兜底
    modules/           原生模块槽位，见 PLATFORM_MODULES.md
  gen/                 `tauri android init` 生成 android/；schemas/ 由 tauri-build 每次构建生成
permissions/autogenerated/  tauri-build 生成的权限参考（不要手改）
```

## 前置

| 目标 | 需要 |
|---|---|
| Windows 桌面 | Rust 1.99.1（`rust-toolchain.toml` 自动安装）、WebView2（Win11 预装；Win10 多数已随更新安装，缺失时安装包会下载） |
| Android | JDK 17、Android SDK（API 34）、NDK 26、Rust 四个 android target |
| 通用 | Node 22.12+、pnpm 10 |

```sh
rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
```

## 常用命令

```sh
pnpm tauri:dev        # 起 rspack(8090) + Tauri 窗口，热更新
pnpm tauri:build      # 出安装包（Windows: NSIS + MSI；首次需联网下载 NSIS / WiX）
pnpm tauri:android:init      # 生成 src-tauri/gen/android
pnpm tauri:android:dev       # 真机/模拟器调试
pnpm tauri:android:build     # 出 arm64 APK（--apk --target aarch64）
```

`tauri.conf.json` 已经把两个钩子接好：

- `beforeDevCommand: pnpm dev:tauri`（带 `APP_TARGET=tauri` 的开发服务器）
- `beforeBuildCommand: pnpm build:tauri`

## 运行时策略：不随包 WebView2

桌面端**不再打包固定版本 WebView2**（`bundle.windows.webviewInstallMode` 已移除），只依赖系统 Evergreen 运行时：

- Windows 11 预装 Edge WebView2；Windows 10 多数已随 Edge/Windows Update 安装，缺失时安装包会通过 Tauri 的 `downloadBootstrapper` 自动下载安装；
- 不再出现“随包运行时与系统架构/版本不匹配”的启动失败，安装包也不会多出数百 MB；
- 仓库里不再有 `src-tauri/webview2/`（约 680MB、且原先被 `.gitignore` 忽略），干净 clone 和 CI 可以直接构建。

只有确实需要离线/锁定内核时才考虑固定运行时，此场景请改用 `offlineInstaller`（把运行时做进安装器），而不是 `fixedRuntime`（运行时会强制 `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` 指向随包目录）。

桌面端已接入 `tauri-plugin-single-instance`：重复双击只唤起已有窗口，不会开出多个进程争用同一个 WebView2 用户数据目录。

**数据目录兜底**：WebView2 默认用户数据目录是 `%LOCALAPPDATA%\com.letmuts.dskchat`。本机实测：当程序装在非系统盘（如 `D:\...`）而数据目录在 `C:` 时，WebView2 环境创建会挂起（窗口一直不出现）。`src-tauri/src/lib.rs` 的 `prepare_webview_data_folder()` 会在两者不同卷时，把数据目录改到 exe 同卷的 `.webview2-data/`；正常装在系统盘时仍使用 `%LOCALAPPDATA%`。

## 版本锁

| 组件 | 实际版本 |
|---|---|
| Rust 工具链 | 1.99.1（`rust-toolchain.toml`） |
| `tauri` / `tauri-build` | 2.12.0 / 2.7.0 |
| `wry` / `tao` | 0.57.3 / 0.37.3 |
| `webview2-com` | 0.39.1 |
| `tauri-plugin-opener` / `tauri-plugin-single-instance` | 2.5.4（vendor） / 2.5.5 |
| JS `@tauri-apps/api` / `@tauri-apps/cli` | 2.12.5 / 2.12.6 |

以 `src-tauri/Cargo.lock` 与 `pnpm-lock.yaml` 为准；`Cargo.toml` 里 `tauri` 写成 `=2.12`，锁文件解析到 2.12.0。

**为什么仍要小心升级**：`tauri` 2.12.x 曾在本机（Windows 10 22H2 + WebView2 157）复现 `msedgewebview2.exe` 启动即崩——事件日志为 `msedge.dll` + 异常码 `0x80000003`（Chromium 的 `IMMEDIATE_CRASH`），Tauri 侧表现为 `WebView2 error: HRESULT(0x8000FFFF)`。后续定位到启动失败的根因是 **WebView2 用户数据目录与 exe 跨卷**（见上节「数据目录兜底」）；当时临时回退到 2.11.x，现在锁文件已回到 2.12.0，说明版本本身不是充分条件。

因此：`wry` 的 WebView2 环境创建代码（`CreateCoreWebView2EnvironmentWithOptions`、默认 `--disable-features`）在 0.55.x / 0.57.x 间基本一致，版本差异未必是原因；**升级前必须跑 Windows 启动测试**，不要把“锁版本”当成根因结论。

`tauri-plugin-opener` 采用 `src-tauri/vendor/tauri-plugin-opener` 的路径依赖，而不是 crates.io 版本：上游 build.rs 在 Android 构建时会往 Cargo registry 缓存目录里复制 `tauri-api`，只读缓存下报 `拒绝访问 (os error 5)`。升级该插件时记得同步 vendor 目录，并把路径依赖指向新版本。

**注意**：

- `Cargo.lock` 必须提交，**不要随意 `cargo update`**；升级可能改动 `wry` / `tao` / `webview2-com` 等传递依赖，升级前请跑 CI 的 Windows 启动测试。
- JS 侧 `@tauri-apps/api`、`@tauri-apps/cli` 与 Rust `tauri` 保持同一 minor（当前 2.12.x），避免 codegen/ACL 漂移。

## 启动失败诊断

启动失败不再静默退出：

- 失败信息写入 `%LOCALAPPDATA%\com.letmuts.dskchat\startup.log`（release 也会写）；
- Windows 上同时弹出原生错误框，提示日志位置；
- panic 会被记录（release），主线程 panic 还会弹框；`[profile.release]` 已不再使用 `panic = "abort"`。

排查顺序：

1. 看 `startup.log` 的最后一条；
2. 若是 `WebView2 error`，先确认系统 WebView2 是否安装/可升级（`winget upgrade Microsoft.EdgeWebView2Runtime`）；
3. 事件查看器 → Windows 日志 → 应用程序，找 `msedgewebview2.exe` / `msedge.dll` 的 `0x80000003` 记录；
4. 需要更细的日志时，设置 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--enable-logging --v=1` 再启动。

## CSP

`tauri.conf.json` 的 `app.security.csp` 已按本项目收敛：

- `connect-src` 放行 `https://api.deepseek.com`、Tauri IPC（`ipc:` / `http://ipc.localhost`）以及 8090 端口的开发服务器（`http://localhost:8090` / `ws://localhost:8090`，用于热更新）；
- KaTeX / Mermaid 需要内联样式，所以 `style-src` 保留 `'unsafe-inline'`；
- 音频、图片走 `blob:`，图片来源另放行 `https:`（搜索结果缩略图）。

**改动前端请求域名时，必须同步改这里**，否则会被静默拦截（控制台报 CSP 违规）。

## 发布

| 平台 | 需要 |
|---|---|
| Windows | `bundle.targets = all` 会同时打 NSIS 与 MSI；NSIS 按用户安装（`nsis.installMode = currentUser`，无需管理员）；首次打包需联网下载 NSIS / WiX；代码签名证书建议配置 |
| macOS | Apple Developer ID + 公证；CI 产出 universal dmg（arm64 + x86_64） |
| Android | keystore；`gen/android` 里配置 `signingConfigs` |

自动更新（`tauri-plugin-updater`）尚未接入：需要先确定发布端点并提供 `TAURI_SIGNING_PRIVATE_KEY`，再开启 `createUpdaterArtifacts`；当前通过安装包手动升级。

## CI

**现状**：`.github/workflows/` 下的三个文件名为 `*.yml.1`，GitHub Actions 不识别，因此推送或打 tag 都不会触发构建。改名为 `.yml` 即可启用。

- `tauri-desktop.yml.1`：矩阵为 Windows（NSIS + MSI，含启动冒烟）、macOS universal（arm64 + x86_64 的 dmg）、Linux（deb + rpm）；先跑 `pnpm type`、`pnpm lint`、`cargo metadata --locked`，再打包；Windows 冒烟检查进程存活、主窗口标题为 `dskchat`、且没有新增 `startup.log`，结束时用 `taskkill /T` 清理进程树。
- `tauri-android.yml.1`：Ubuntu 上装 JDK 17 / Android SDK 34 / NDK 26，每次重新 `pnpm tauri:android:init` 后构建 APK；上传 `apk/**` 与 `bundle/**`。
- `pages.yml.1`：推送到 `main` 时构建静态站点并部署到 GitHub Pages；它固定了 Node 24 与 pnpm 12.6，与仓库要求的 Node 22 / pnpm 10 不一致，启用前先统一版本。

启用方式：

```sh
git mv .github/workflows/tauri-desktop.yml.1 .github/workflows/tauri-desktop.yml
git mv .github/workflows/tauri-android.yml.1 .github/workflows/tauri-android.yml
git mv .github/workflows/pages.yml.1 .github/workflows/pages.yml
```

> 启用后推送到 `main` 会同时触发 Pages 部署；桌面 / Android 工作流只在打 `v*` tag 或手动 `workflow_dispatch` 时运行。

## 排错

| 现象 | 原因 |
|---|---|
| 窗口白屏 | 先看是不是 `pnpm build:tauri` 没跑；再确认 `frontendDist` 指向 `../dist` |
| 接口全部失败、控制台 CSP 报错 | `connect-src` 少了域名 |
| 语音按钮不可用 | 麦克风权限未授予；`isSecureContext` 为 false |
| Android 授权后仍提示无法使用麦克风 | AndroidManifest 缺 `MODIFY_AUDIO_SETTINGS`（wry 的授权链路要求它和 `RECORD_AUDIO` 同时通过），见 `docs/ANDROID.md` |
| `cargo check` 卡在下载 | 首次编译 Tauri 依赖较重，属于正常 |
| 启动即退出 | 看 `%LOCALAPPDATA%\com.letmuts.dskchat\startup.log`；Windows 还会弹错误框 |
| 事件日志出现 `msedgewebview2.exe` / `msedge.dll` / `0x80000003` | WebView2 内核启动失败：先升级/重装系统 WebView2；仍复现则抓 dump，不要只靠换版本 |
| `tauri build` 报锁文件需要更新 | 说明 `Cargo.lock` 与 `Cargo.toml` 不一致；本地 `cargo update` 后提交锁文件，CI 用 `cargo metadata --locked` 校验 |
| 打包停在 `Downloading ... nsis-3.11.zip` / `wix314-binaries.zip` | 首次打包需要联网下载 NSIS / WiX；受限网络会报 ``failed to bundle project: `timeout: global` ``。exe 此时已生成，可先用 `pnpm tauri build --bundles nsis`，或预置缓存后再打包 |
| Android 构建报 `failed to copy tauri-api ... 拒绝访问 (os error 5)` | `tauri-plugin-opener` 的 build.rs 要往 Cargo registry 缓存写文件；仓库已 vendor 到 `src-tauri/vendor/` 并用路径依赖，若仍报错请检查是否误用了 crates.io 版本或 `CARGO_HOME` 只读 |
| 改 `identifier` 后找不到 `startup.log` | 该路径在 `lib.rs` 里硬编码为 `com.letmuts.dskchat`，需与 `identifier` 一起改 |
